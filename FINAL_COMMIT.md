This is human handwriting. Thank you for using PURU-AI / PURUCLAW, I USED REFERENCES FROM 2 POPULAR PUBLIC REPOSITORIES, NAMELY PICOCLAW AND OPENCLAW.

This final commit is because I've verified that context management, memory, agent memory, and everything else are ready for daily use. I think the project is mature here. 

October 7, 2026: Agents can receive document files and save them to the workspace and inject their absolute path into the prompt. 

October 16, 2026: `puru setup` became a real wizard. Questions are grouped in sections with colors (auto-plain when piped, NO_COLOR, or not a TTY), secrets are masked in a preview panel before the file is written, and every field defaults to the existing config.json, so pressing Enter keeps the current setup (env vars still win, and the minimal wizard carries over the rest). Shipped as v6.1.0 on GitHub Releases and npm.

October 17, 2026: PURU-AI now runs on the phone itself. `android/` holds a self-contained launcher APK: the same Go binary ships inside the APK as `libpuru.so` (the only directory Android 10+ still lets an app execute from), the config form writes config.json through `puru setup` so the Go binary stays the only writer, and `puru gateway` lives in a foreground service with a Start/Stop UI, log view, and a launcher notification. The Android APK workflow cross-builds arm64-v8a/armeabi-v7a per commit, keeps the signing key stable so a newer APK installs over the old one, builds the APK inside the release run itself (a tag pushed with GITHUB_TOKEN cannot trigger another workflow, so the Release workflow calls it as a reusable workflow) and attaches it to the tag, and pushes a build report to the `debug-android-build` branch because job logs are not readable without admin rights.

October 17, 2026 (evening): the launcher was tested on a real phone (Realme RMX2185, Android 10) — the bundled binary starts, the form loads the existing config, and the gateway log is visible on screen, which is how the real bug showed up: Android has no /etc/resolv.conf, so the pure-Go resolver fell back to `[::1]:53` and `puru gateway` died on `getMe` with "connection refused". Go's own net/conf.go says it: "DNS requests don't work on Android, so prefer the cgo resolver". The bundled binary is now built `GOOS=android` with cgo through the runner's NDK, so lookups go through bionic/netd like every other Android app. The same debugging session added the config form the wizard always had: one table of rows in MainActivity.kt (label, env var, hint, required/advanced flag) builds the UI, required rows (bot token, base URL, model name) are marked red and validated before saving, optional rows are grey and an empty one keeps the config.json value, and the runtime/skills/web-search knobs sit behind "Show advanced settings". Every wizard field now has an env override, so a GUI can drive `puru setup` without a terminal, and the child process runs with NO_COLOR=1 so the log view shows plain text. Releases are also automatic now: pushing a version tag (`v6.3.0` or `V6.3.0`) runs the Release workflow for that exact tag, a manual run still bumps from the newest v*/V* tag, and the npm installer tries both prefix spellings so an uppercase release stays installable. The launcher can also import a config.json picked from the phone's storage: the file is validated by `puru setup` on a scratch copy and only then replaces the live config, so a config exported from the laptop can move to the phone without retyping secrets.

October 18, 2026: the phone build stops being a toy. `web_fetch` was handing raw bytes to the model, so any page that is not UTF-8 (or any body cut mid-character at the 2 MB cap) arrived as mojibake: bodies are now decoded to UTF-8 using the charset from the Content-Type header or an HTML meta tag, undeclared 8-bit pages fall back to windows-1252 like a browser, and the result is always valid UTF-8. The agent can also finally touch real files: the launcher targets API 28 with `requestLegacyExternalStorage` (the same trade-off Termux makes) and asks for the classic storage permission, the workspace moves to `/sdcard/PURU-AI/workspace` — visible in any file manager and over USB — an old app-private workspace is migrated after every copied file is verified, and with `restrict_workspace` off the file tools can read, write and delete anywhere on /sdcard. Scoped storage (targetSdk 30+), `MANAGE_EXTERNAL_STORAGE` on Android 10, and SAF tree permissions were all ruled out: none of them give the Go binary a path it can open. The shell gets the same treatment: two new commands, `puru doctor` (config, workspace write/delete, HOME, TMPDIR, the spawned shell, tools on PATH, DNS, HTTPS — one look at why a phone build misbehaves) and `puru fetch -o FILE URL` (downloads through the bot's own Go stack, so TLS and DNS work where toybox cannot, sets +x for ELF and shebang files, downloads to `.part` and renames so a failed transfer never truncates anything). `$HOME/bin` and the native library directory are on PATH, `puru` is symlinked into `$HOME/bin`, and config.json can be exported as well as imported. Release APKs are debuggable on purpose, because supporting a sideloaded launcher means `adb shell run-as`.

October 18, 2026 (evening, on the phone): everything above was checked on the real device (Realme RMX2185, Android 10), not just in CI. `puru doctor` runs as the app user and reports DNS for api.telegram.org and the model endpoint in tens of milliseconds, HTTPS reachable, and `/sdcard/PURU-AI/workspace` writable — so the old "http/https dari shell kena block dns" was never DNS, it was the missing tools (Android ships no curl, and toybox wget has no TLS). A Shift_JIS page (aozora.gr.jp) fetched through the agent came back as clean Japanese instead of mojibake, `/sdcard/Download` accepted a write and a delete from the app user, a binary copied into `$HOME/bin` executed, and `puru fetch` wrote both `$HOME/bin` (marked executable) and the shared workspace. v6.5.1 fixes the one thing the update itself exposed: an app update extracts the libraries into a new directory, so `$HOME/bin/puru` is now refreshed instead of dangling.
