# AGENTS.md

## Mulai Cepat
- Salin `example.config.json` → `~/.puru/config.json` (`/root/.puru/config.json` untuk root), isi `telegram_bot_token` + `model`.
- `go run . --config ~/.puru/config.json` — jalankan bot (config JSON tunggal, tanpa `.env`, tanpa web UI).
- `go run ./cmd/cli "pesan..."` — chat langsung dengan agent (debug, tanpa Telegram; REPL bila tanpa argumen).
- `go vet ./...` — static analysis.
- `go test ./...` — unit test (ai, config, history, prompt, messages, telegram, openai, memory, app).
- `gofmt -l .` — cek format.

## Konfigurasi (config.json saja)
- Satu-satunya sumber config: JSON (`internal/config/config.go`). Urutan path: flag `--config` > env `PURU_CONFIG` > `~/.puru/config.json`.
- Isi: `telegram_bot_token`, `telegram_allowed_users` (array ID Telegram, kosong = semua boleh), `model{base_url,api_key,model,temperature}`, `workspace` (default `~/.puru/workspace`), `restrict_workspace` (default `true`), `max_iterations` (default `500`), `history_token_limit` (default `30000`), `host` (default `0.0.0.0`) + `port` (default `8080`) khusus health check (`GET /health`), `tools_preview` (default `true`: edit-message live tools yang dipakai AI), `loop_delay_seconds` (default `3`, clamp maks `60`: jeda antar loop/iterasi agent), `exec_memory_mb` (default = min `64`: budget RAM grup proses tiap `exec`, lewat → di-kill di Linux).
- Tidak ada `.env`, web UI, Firebase, settings per-user, providers, combos, relay/proxy, E2B/sandbox, skills, scheduler, vision. Semua itu dihapus.

## Arsitektur (Go, module `github.com/purujawa06-bot/PURU-AI`, lightweight)
- `main.go` — set `debug.SetMemoryLimit(50<<20)` (GOMEMLIMIT 50MB) → load config → satu model OpenAI-compatible (`internal/ai/openai`) → history lokal → agent → Telegram polling + health server (`internal/health`, `GET /health` di `host:port`) di goroutine. Boot cepat: tanpa web server, tanpa Firebase, tanpa init berat.
- `cmd/cli` — wiring sama minus Telegram (debug 1:1).
- `internal/config` — loader JSON + default + validasi + `mkdir workspace/history`.
- `internal/ai` — agent langchaingo (`agents.Executor`, max iterasi = `max_iterations`, jeda antar loop = `LoopDelay()` di `Plan`) + **11 tools** (`tools.go`, deklarasi tiru picoclaw): `read_file` (path, offset, length; 64KB max; respons header `[file: base | total | read]` + `[TRUNCATED ... offset=X ...]`/`[END OF FILE ...]`), `write_file` (path, content, overwrite; tanpa overwrite file ada → tolak + arahkan ke append/edit), `list_dir` (path; baris `DIR:`/`FILE: [size]`, terurut direktori dahulu, dir kosong → `(empty directory)` agar model tidak looping), `edit_file` (path, old_text, new_text — unik, respons `File edited: path`), `append_file` (path, content; respons `Appended to path`), `exec` (action wajib: run/list/poll/read/kill ala picoclaw — `run` blocking default / background bila `background=true` (return sessionId), `list`/`poll`/`read`/`kill` kelola sesi thread-safe (RWMutex sesi + `cappedWriter` ber-mutex, max 20 sesi tersimpan: finished terlama di-evict, running tak pernah di-evict, `list` terurut sessionId, `kill` langsung tandai sesi finished agar `poll`/`read`/`list` tak lagi lihat running); `command` wajib untuk `run`, `sessionId` wajib untuk poll/read/kill; `read` kembalikan output + status/flag diagnosis sama seperti `poll` (`status`, `timed_out`, `memory_limited`); output di-cap 20k char) + `telegram_sendfile` (butuh `Agent.Telegram` + `opts.ChatID`, file di-jail, cap 20MB, validasi size via `os.Stat` sebelum baca; param path/filename/caption), `telegram_getuser` (tanpa arg = `opts.User` si penanya; `user_id` = fetch live via `getChat`: nama, id, username, bio; keduanya error-value ramah bila tanpa konteks Telegram/CLI), `get_env` (info lingkungan sistem dan RAM), `web_search` (query wajib non-kosong, count opsional default 5 clamp 1-10; Yahoo HTML + fallback Bing HTML, stdlib saja, hook `OnTool` tetap jalan), dan `web_fetch` (url wajib http/https publik — tolak file:// dan host lokal/private; max_chars opsional default 8000 clamp 1000-20000; body di-cap ~100KB, strip HTML jadi teks + marker truncate). Tiap tool `Run` dibungkus hook `opts.OnTool(name, args)` untuk preview live. `model.go` = `retryModel`: **setiap pemanggilan API selalu streaming** (agent `Plan` selalu pasang `StreamingFunc` → `stream:true`; `Compact` summarize non-streaming) dan **API error di-retry total 5x dengan jeda 2 dtk per model call** (tools yang sudah jalan tidak diulang). `fs.go` = jail workspace (`restrict_workspace`: tolak path absolut di luar workspace + `../` escape; berlaku untuk tools DAN `exec` cwd; `resolveWorkdir` pastikan cwd ada + berupa direktori dengan pesan jelas agar `cmd.Start` tak gagal generik) + helper `readLocalFile`/`writeLocalFile`/`appendLocalFile`/`listLocalDir`/`editLocalFile` (binary ditolak di read). `exec.go` = shell dengan timeout: default 60 dtk bila agent tidak mengisi `timeout`, clamp maks 300 dtk; output di-capture bounded 20k char + marker `...[truncated, total X]` (buffer tidak pernah lebih dari cap); tiap command di-budget RAM `exec_memory_mb` (watcher RSS grup proses per 200ms via `/proc`, Linux saja, lewat → `SIGKILL` + flag `memory_limited`; `ulimit -v` sengaja TIDAK dipakai karena merusak toolchain Go/Java yang butuh VSZ besar); file yang ditulis command di-cap 100MB via `ulimit -f` (unix, best-effort); timeout → kill process group (unix `setpgid` + `SIGKILL`, lihat `exec_unix.go`/`exec_windows.go`, watcher di `exec_mem_linux.go` + stub `exec_mem_other.go`) agar tidak bocor RAM.
- `internal/history` — history per-chat di `~/.puru/history/{chatID}.json` (map in-memory + disk). **Tidak pernah di-trim/cap** — tumbuh sampai trigger kompak.
- `internal/memory` — `Compact(ctx, msgs) (rel, err)`: bila history ≥ `history_token_limit` (30k default) SEBELUM prompt baru, model meringkas seluruh history (transkrip `role: teks` incl. tool-call/tool-result dengan output tool dipangkas ke 1000 karakter, tanpa reasoning) jadi markdown (`## Key facts/Done/Pending/Notes`, maks ~400 kata, non-streaming 1 call) ke `<workspace>/context/YYYY-MM-DD_HH-MM-SS.md` (nama = tanggal+jam saja; tabrakan detik `-2/-3`), prune ke 20 file terbaru (by modtime, `.json` lama ikut kehitung supaya punah alami), lalu history di-wipe total; ringkasan TERBARU selalu di-inject ke system prompt (`memory.LatestSummary`, `prompt.Get(memory, summary)`). Gagal summarize = error, history dipertahankan (retry pesan berikutnya); tanpa model = fail-closed. **Tidak menyentuh MEMORY.md.** Dipicu di `internal/app` + `cmd/cli` (`mem.Model = llm`).
- `internal/app` — handler Telegram slim (teks saja, busy-guard per-user via `*busySession` berisi cancel func, allowlist `telegram_allowed_users`: kosong = semua boleh, selain itu tolak + log `[app] blocked unauthorized`; grup group/supergroup diam kecuali `/ai <pertanyaan>` (prefix dikupas, `/ai` kosong → contoh pakai; `/aid` dkk ditolak) atau command instan, private proses semua teks; menu terdaftar `/help`/`/clear`/`/token`/`stop` via `SetMyCommands`; `/token` = `tokenInfo`: % konteks penuh (system prompt render + history incl. tool-call/tool-result/reasoning) vs `history_token_limit` menuju summarize, Markdown fallback, >4096 char → file; `/stop` = `stopUser`: cancel request ctx user + lepas busy (CompareAndDelete, race-safe vs sesi baru), `runExec` blocking ikut di-kill via parent ctx (background dikecualikan via WithoutCancel, matikan via kill), Markdown fallback, >4096 char → file). `processMessage` mengisi `ProcessOptions{ChatID, User, OnTool}`; `previewHook` edit pesan `🤔 ...` live (`🔧 tool arg`, throttle 1.2 dtk, maks 6 baris) bila `tools_preview=true`.
- `internal/prompt` — system prompt Inggris ringkas (11 tools ala picoclaw, aturan workspace + kapan pakai web_search/web_fetch, MEMORY.md = fakta permanen yang BOLEH ditulis agent — nama/hobi/info pribadi, tanpa info sementara; ringkasan terbaru `context/*.md` di-inject sebagai Conversation Summary, system-managed).
- `internal/messages`, `internal/tokens`, `internal/telegram`, `internal/ai/openai` — dipertahankan (skema history Vercel-compatible, hitung token o200k_base atas seluruh konteks: system prompt + semua role + tool-call args + tool-result output + reasoning + overhead framing 3/pesan, `Part.ToolCallText`/`ResultText` dipakai bersama request builder agar tak drift, adapter Telegram via **telego** long-polling, transport OpenAI streaming).

## Perilaku Penting
- **Satu model, satu attempt per run**: tanpa fallback provider. Tiap model call streaming + API error di-retry total 5x jeda 2 dtk; gagal total = balasan `Maaf, saya tidak bisa merespons saat ini.` + log `[ai]`.
- **Tool timeout**: wrapper tool 330 dtk (melebihi exec maks 300 dtk); total agent 20 menit.
- **MEMORY.md ditulis agent** (fakta permanen: nama, hobi, info pribadi, preferensi tetap via `edit_file`/`exec`); compactor DILARANG menyentuhnya; jangan simpan info sementara di sana.
- **Ringkasan di `context/`, yang terbaru di-inject** — compact = model summarize → `.md`; isi ringkasan TERBARU selalu masuk system prompt; file lama hanya referensi via `read_file` bila perlu.
- **GOMEMLIMIT 50MB**: `debug.SetMemoryLimit` di `main.go`/`cmd/cli` + `ENV GOMEMLIMIT=50MiB` di `Dockerfile`.
- **Workspace**: `restrict_workspace=true` = AI tidak bisa baca/tulis/eksekusi di luar workspace lewat jalur apa pun.
